# knowledge-vault-generation ヒアリング記録

**作成日**: 2026-08-13
**ヒアリング実施**: step4 既存情報ベースの差分ヒアリング

## ヒアリング目的

`intrahub-mastra` の PRD は完成度が高く、機能要求 FR-001〜FR-015 と非機能要求 NFR-001〜NFR-006 がすでに定義されている。一方で PRD §24「未決事項」に9件の未確定項目が残っており、これらは要件定義の骨格（スキーマ形状、配置規則、書き込み経路）を左右する。そこで **未決事項の解消** と **作業前提の確認** に絞ってヒアリングを実施した。

## 事前準備（step3で収集した情報）

- `intrahub-mastra/docs/` には PRD.md と codex-chat.md のみ。既存の spec / rule ディレクトリは無し
- `src/mastra/` は weather サンプル構成（6ファイル）のみ。全ファイルを読了済みのため、追加のコードベース調査は不要と判断しスキップした
- `models/litellm.ts` は `wiki-model` 1本のみで、PRD §11 の Agent 別モデル割当に未対応
- `@mastra/mcp` が package.json に未導入

### Q3: Knowledge Vault の git 管理（PRD §24-9）

**質問日時**: 2026-08-13
**カテゴリ**: 既存設計確認 / 追加要件
**背景**: PRD §24-9 は「git 管理して定期 commit するか。上書き事故が事後回復可能になり、FR-014 の重要度が下がる」と記載している。採否によって NFR-004（再実行可能性）と §12.2「更新前後の差分を監査可能な形式で保持する」の実現手段が変わる。

**回答**: **git 管理する**

**信頼性への影響**:
- 新規要件 REQ-019 を追加（🔵）。未決事項 §24-9 を解消
- NFR-042（差分の監査可能性）の実現手段が git commit に確定（🔵 へ昇格）
- 派生して EDGE-005（commit 失敗時の扱い）と EDGE-107（空白のみの差分で commit しない）を追加（いずれも 🟡）
- なお FR-014（REQ-018 の一致確認）は**重要度を下げない**方針とした。git は事後回復手段であり、ロストアップデートの防止そのものではないため

### Q5: `get_item_text` のチャンク参照の統一（PRD §24-1）

**質問日時**: 2026-08-13
**カテゴリ**: 未定義部分詳細化
**背景**: PRD §24-1 は「PDF ページ、EPUB 章、固定文字数チャンクをどう統一して参照するか」を未決としている。`ResearchResult.sources[].chunks` と frontmatter の `sources[].chunks` のスキーマ形状が決まらないため、PRD §21-1（スキーマ確定）に着手できない。

**回答**: **連番インデックス統一**。MediaVault 側が形式差を吸収し、`intrahub-mastra` は `(fileId, chunkIndex)` だけを扱う。表示用ラベルは任意の付属情報。

**信頼性への影響**:
- REQ-006 を追加（🔵）。未決事項 §24-1 を解消
- PRD §13.1 の `chunks?: Array<{ index: number; extractedAt?: string }>` と §14 の `chunks: [0, 1]` がそのまま使える形に確定した
- **MediaVault 側への依存が1件増えた**。`get_item_text` が形式差を吸収した連番インデックスを返すことが前提になるため、prep.md の確認事項へ記載した

### Q6: `second-brain` 配下のノート配置規則（PRD §24-5）

## ヒアリング結果サマリー

### 確認できた事項

- 対象範囲は MVP-0 + MVP-1。Critic と Supervisor は要件化しないが、追加余地は `status` 設計で確保する
- 曖昧時の振る舞いは `ambiguous` 終了で一意に確定（suspend はオプション）
- MVP のノート種別は `source` / `work` / `concept` の3種
- `sourceRefs` は `(fileId, chunkIndex)` の連番インデックスで統一
- 既存コードは weather サンプルのみで、置き換え対象と再利用対象が明確
