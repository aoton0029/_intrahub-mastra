## REQ-001〜REQ-004: Vault 構成とノート規約 🔵

**信頼性**: 🔵 *PRD §5・codex-chat.md「Knowledge Vaultの構成」「ノート種別」「メタデータと出典」より*

### Given（前提条件）
- `/workspace/second-brain` がマウントされている
- Vault 規約（7大分類・`type` 11種・共通 frontmatter・`status` 5値）が定義済み

### When（実行条件）
- 任意の Workflow がノートを生成する

### Then（期待結果）
- ノートが7大分類のいずれかの配下に置かれる
- frontmatter に `id` / `title` / `type` / `aliases` / `categories` / `tags` / `status` / `sources` / `source_refs` / `provenance` が揃っている
- `type` が11種のいずれかである
- `status` が5値のいずれかである

### テストケース

#### 正常系
- [ ] **TC-001-01**: 生成ノートの frontmatter スキーマ検証 🔵
  - **入力**: 生成された章ノート1件
  - **期待結果**: zod スキーマ検証を通過し、必須10フィールドがすべて存在する
  - **信頼性**: 🔵 *codex-chat.md frontmatter 例より*
- [ ] **TC-002-01**: `type` の値域検証 🔵
  - **入力**: `type: chapter` のノート
  - **期待結果**: 11種の許可リストに含まれるため受理される
  - **信頼性**: 🔵 *codex-chat.md「ノート種別」より*
- [ ] **TC-004-01**: `status` の値域検証 🔵
  - **入力**: `status: draft` のノート
  - **期待結果**: 5値の許可リストに含まれるため受理される
  - **信頼性**: 🔵 *codex-chat.md `status` 表より*

#### 異常系
- [ ] **TC-002-E01**: 未定義の `type` を拒否する 🟡
  - **入力**: `type: unknown_kind`
  - **期待結果**: スキーマ検証失敗として拒否し、Vault へ書き込まない（NFR-031「スキーマ検証失敗」）
  - **信頼性**: 🟡 *NFR-031 の失敗分類から妥当な推測*
- [ ] **TC-003-E01**: 必須 frontmatter 欠落を拒否する 🟡

  - **期待結果**: 書き込み前に検証失敗として拒否される
