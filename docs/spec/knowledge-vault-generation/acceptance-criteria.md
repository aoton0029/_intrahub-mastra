## REQ-001 / REQ-020 / REQ-101: Item ID からの知識生成（metadata_only） 🔵

**信頼性**: 🔵 *PRD §10 FR-001・§12.1・§20*

### Given（前提条件）
- MediaVault MCP へ Bearer トークンで接続できる
- 対象 Item が MediaVault に存在する
- `get_item_text` は未実装である

### When（実行条件）
- `generateItemKnowledgeWorkflow` を `{ itemId, mode: "metadata_only", dryRun: false }` で実行する

### Then（期待結果）
- Workflow が `status: "success"` または `"partial"` で完了する
- `WorkflowResult` に `created` / `updated` / `unchanged` / `ambiguous` / `sources` / `warnings` / `errors` がすべて含まれる
- `get_item_text` 未実装が失敗要因にならない

### テストケース

#### 正常系

- [ ] **TC-001-01**: 有効な Item ID で完了する 🔵
  - **入力**: 実在する Item ID、`mode: "metadata_only"`、`dryRun: false`
  - **期待結果**: `status: "success"`、`created` に1件以上のノート
  - **信頼性**: 🔵 *PRD §20 受け入れ基準1・2より*

- [ ] **TC-001-02**: `get_item_context` の呼び出し内容が正しい 🔵
  - **入力**: 同上
  - **期待結果**: MCP へ `get_item_context` が Item ID 付きで1回呼ばれる。書き込み系ツールは一切呼ばれない
  - **信頼性**: 🔵 *PRD §10 FR-001・§15より*

#### 異常系

- [ ] **TC-001-E01**: MCP 接続失敗を接続失敗として返す 🔵
  - **入力**: 到達不能な MCP エンドポイント
  - **期待結果**: `status: "failed"`、`errors` に接続失敗種別。スキーマ検証失敗と区別できる
  - **信頼性**: 🔵 *PRD §20 受け入れ基準7・NFR-003より*

- [ ] **TC-001-E02**: 存在しない Item ID で Vault へ書き込まない 🟡
  - **入力**: 存在しない Item ID
  - **期待結果**: `status: "failed"`、Vault のファイル数が実行前後で不変
  - **信頼性**: 🟡 *EDGE-002。PRD NFR-003 から妥当な推測*

## REQ-002 / REQ-023 / NFR-011: 構造化データの契約 🔵

**信頼性**: 🔵 *PRD §10 FR-002・§12.1・NFR-001*

### Given（前提条件）
- `ResearchResult` の Zod スキーマが定義されている

### When（実行条件）
- `mediaResearchAgent` が調査結果を返す

### Then（期待結果）
- 出力が Zod 検証を通過する
- 検証に失敗した場合、自然文へフォールバックせず Step が失敗する

### テストケース

#### 正常系

- [ ] **TC-002-01**: `ResearchResult` が全フィールドを備える 🔵
  - **入力**: 通常の Item コンテキスト
  - **期待結果**: `topic` / `sources` / `claims` / `concepts` / `relationships` / `uncertainties` がすべて存在し、`claims[].kind` が4値のいずれか、`confidence` が数値
  - **信頼性**: 🔵 *PRD §13.1より*

- [ ] **TC-002-02**: 各 Step が `inputSchema` と `outputSchema` を持つ 🔵
  - **入力**: Workflow 定義の静的検査
  - **期待結果**: 6 Step すべてにスキーマが定義されている
  - **信頼性**: 🔵 *PRD §12.1・REQ-022より*

#### 異常系

- [ ] **TC-002-E01**: スキーマ検証失敗が次工程へ流れない 🔵
  - **入力**: `claims[].kind` に不正値を返すモック Agent
  - **期待結果**: 当該 Step が失敗し、`writeKnowledgeDrafts` が実行されない。`errors` にスキーマ検証失敗種別
  - **信頼性**: 🔵 *EDGE-003・PRD §19「schema validation を通らない Agent 間データの次工程流入 0件」より*

  - **信頼性**: 🔵 *PRD §13.1・§14より*

  - **期待結果**: `not_extracted` を含む `status: "partial"`。知識生成は部分完了または保留
  - **信頼性**: 🔵 *PRD §9.2・REQ-103より*

- [ ] **TC-004-E02**: `get_item_text` 未実装時に `full_text` が失敗種別を区別して返す 🔵

## REQ-012 / REQ-106 / REQ-111: 重複回避と冪等性 🔵

**信頼性**: 🔵 *PRD §10 FR-004・§12.2・§19・§20*

### Given（前提条件）
- 同一 Item について1回目の生成が完了している
- 原典バージョンと生成設定に変更がない

### When（実行条件）
- 同じ Item で2回目を実行する

### Then（期待結果）
- 同一概念の新規ノートが増えない
- 内容差分がなければ `unchanged` が返る

### テストケース

#### 正常系

- [ ] **TC-012-01**: 2回実行しても新規ノートが増えない 🔵
  - **入力**: 同一 Item を連続2回実行
  - **期待結果**: 2回目の `created` が空、`unchanged` に1回目のノートが列挙される。Vault のファイル数が不変
  - **信頼性**: 🔵 *PRD §20 受け入れ基準4・§19より*

- [ ] **TC-012-02**: 4観点での照合が行われる 🔵
  - **入力**: title は異なるが alias が一致する既存ノート
  - **期待結果**: 既存ノートが候補として検出される（title のみの照合では見逃す）
  - **信頼性**: 🔵 *PRD §10 FR-004・§23より*

- [ ] **TC-012-03**: 部分成功後の再実行で重複しない 🔵
  - **入力**: 1回目が部分失敗（一部ノートのみ作成）、2回目を同条件で実行
  - **期待結果**: 作成済みノートは `unchanged` または `updated`、失敗分のみ `created`
  - **信頼性**: 🔵 *NFR-004・PRD §12.2より*

#### 境界値

- [ ] **TC-012-B01**: 候補1件完全一致は更新、2件以上は曖昧 🔵
  - **入力**: (a) 完全一致候補1件 (b) 該当候補2件
  - **期待結果**: (a) `updated` または `unchanged` (b) `ambiguous`
  - **信頼性**: 🔵 *EDGE-106、ユーザヒアリング 2026-08-13より*

- [ ] **TC-012-B02**: 差分が空白・改行のみなら `unchanged` 🟡
  - **入力**: 末尾改行だけが異なる生成結果
  - **期待結果**: `unchanged`。ファイル書き込みと git commit が発生しない
  - **信頼性**: 🟡 *EDGE-107。PRD §12.2 から妥当な推測*

## REQ-018 / REQ-105 / REQ-413: 競合検出 🔵

**信頼性**: 🔵 *PRD §10 FR-014・§14・§23*

### Given（前提条件）
- Workflow がノートを読み取り、版識別子を導出している

### When（実行条件）
- 書き込み直前に、そのノートが第三者（人間の編集）によって変更されている

### Then（期待結果）
- 上書きせず停止する
- 競合として `errors` に記録される

### テストケース

#### 正常系

- [ ] **TC-018-01**: 一致すれば置換される 🔵
  - **入力**: 読み取り後に外部変更のないノートの更新
  - **期待結果**: `updated` に記録され、内容が置き換わる
  - **信頼性**: 🔵 *PRD §10 FR-014より*

#### 異常系

- [ ] **TC-018-E01**: 不一致なら上書きしない 🔵
  - **入力**: 読み取り後、書き込み前に本文を1文字書き換えたノート
  - **期待結果**: 書き込みが拒否され、外部編集の内容が保持される。競合として区別された失敗が返る
  - **信頼性**: 🔵 *PRD §10 FR-014・§23より*

#### 境界値

- [ ] **TC-018-B01**: 内容不変の `touch` を競合と誤判定しない 🔵
  - **入力**: mtime だけが更新され内容が同一のノート
  - **期待結果**: 競合と判定されず、正常に置換される
  - **信頼性**: 🔵 *PRD §14「同一秒内の保存と内容を変えない touch を両方誤判定する」より*

- [ ] **TC-018-B02**: 同一秒内の内容変更を検出する 🔵
  - **入力**: 読み取りと同一秒内に内容が変更されたノート
  - **期待結果**: 競合として検出される
  - **信頼性**: 🔵 *PRD §14より*

- [ ] **TC-018-B03**: frontmatter に版識別子が存在しない 🔵
  - **入力**: 生成された任意のノート
  - **期待結果**: frontmatter にバージョン・ハッシュ・リビジョン相当のキーが含まれない
  - **信頼性**: 🔵 *REQ-413・PRD §14より*

  - **入力**: `status: reviewed` のノートへ `sources` を1件追加
  - **期待結果**: 成功し、本文は不変
  - **信頼性**: 🔵 *PRD §14 表より*

#### 異常系

- [ ] **TC-201-E01**: reviewed の本文更新を拒否する 🔵
  - **入力**: `status: reviewed` のノートへの本文更新
  - **期待結果**: 拒否され、元ノートが変更されない。保護拒否として区別された結果が返る
  - **信頼性**: 🔵 *PRD §10 FR-015より*

- [ ] **TC-201-E02**: verified の本文更新を拒否する 🔵
  - **入力**: `status: verified` のノートへの本文更新
  - **期待結果**: 同上
  - **信頼性**: 🔵 *PRD §14 表より*

- [ ] **TC-201-E03**: 拒否内容が別ファイルへ書き出される 🔵
  - **入力**: `status: reviewed` のノートへの本文更新
  - **期待結果**: 元ノート不変、修正内容が別ファイルとして存在する
  - **信頼性**: 🔵 *PRD §14・§17・REQ-205より*

- [ ] **TC-201-E04**: status の昇格をツールから行えない 🔵
  - **入力**: `draft` → `reviewed` への status 変更を含む更新
  - **期待結果**: 拒否される（保護を外してから上書きする経路が閉じている）
  - **信頼性**: 🔵 *PRD §14・REQ-204より*

- [ ] **TC-201-E05**: status の降格をツールから行えない 🔵
  - **入力**: `verified` → `draft` への status 変更
  - **期待結果**: 拒否される
  - **信頼性**: 🔵 *PRD §14 表より*

- [ ] **TC-201-E06**: プロンプト指示を無視した Agent の書き込みもコードで拒否される 🔵
  - **入力**: `updateNote` を直接呼ぶ（Agent の指示遵守に依存しない経路）
  - **期待結果**: ツール実装が拒否する
  - **信頼性**: 🔵 *PRD §14「拒否はコードで強制する」・NFR-104より*

### Given（前提条件）
- Knowledge Vault が `/workspace` へ read-write で mount されている
- 配下に `ai-workspace` と `second-brain` が存在する

### When（実行条件）
- Vault 書き込みツールを各種パスに対して呼ぶ

### Then（期待結果）
- `second-brain` へは `createNote` / `updateNote` / `moveNote` のみ到達する
- 自由書き込みツールは `ai-workspace` 配下に限定される
- mount 範囲外への書き込みが拒否される

- [ ] **TC-014-02**: 明示指定で second-brain へ直接書く 🔵
  - **入力**: 出力先モードに `second-brain` を明示
  - **期待結果**: `second-brain/{type}/{topic}/{slug}.md` へ配置される
  - **信頼性**: 🔵 *ユーザヒアリング 2026-08-13（§24-5, §24-6 の決定）・REQ-016より*

- [ ] **TC-014-03**: 読み取りが専用ツールを介さない 🔵

#### 異常系

- [ ] **TC-014-E01**: 相対パス脱出を拒否する 🔵
  - **入力**: `../../etc/passwd` を含むノートパス
  - **期待結果**: 書き込み拒否
